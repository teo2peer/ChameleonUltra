## [unreleased][unreleased]
 - Accelerated automatic MIFARE Classic key discovery while one card remains presented. `MF1_CHECK_KEYS_OF_SECTORS` now selects once and uses UID-pinned fast reselection across candidates instead of resetting the antenna after every failed key, and authenticates trailer-derived Key B values before reporting them. Python and Flutter split dictionary and reused-key scans into bounded target/key batches, derive timeouts from actual authentication attempts, re-authenticate every returned key, preserve command 2015 fallback, and show an explicit keep-card-present warning.
 - Added resumable continuous ISO14443-A capture across Ultra firmware, Python, and Flutter (commands 2021-2025). Emulation, passive reader-command monitoring, and active-reader tracing share an 8 KiB sequence-numbered ring with explicit overflow counters, monotonic timestamps, versioned records, CRC32 pages, durable host-before-ACK semantics, enforced USB/BLE ownership, per-boot session identity, and unsolicited drain notifications. The GUI persists complete atomic pages and checkpoints beyond device RAM, binds resume to chip and boot identity, recovers uncertain START responses, drains stopped sessions after reconnect, archives final loss metadata, exposes configurable safe retention, enables iOS BLE-central background delivery, and fixes MFKey64 evidence handling to require the real encrypted AT instead of substituting another authentication's NT.
 - Fixed a boot loop that made the device connect and immediately disconnect over both USB and BLE (`getDeviceMode`/timeout errors). The keyboard HID feature registered a full BLE HID GATT service at boot (`ble_hids_init` under `APP_ERROR_CHECK`) without enlarging `NRF_SDH_BLE_GATTS_ATTR_TAB_SIZE`, so a full attribute table returned `NRF_ERROR_NO_MEM` and reset the MCU before USB enumeration was even enabled. Keyboard HID is now opt-in and off by default (persistent `keyboard_hid_enable`, commands 1051/1052, `hw keyboard enable on|off`): a disabled device exposes no USB HID interface, advertises no HID UUID, registers no BLE HID service, and forces no on-site BLE pairing — booting byte-for-byte as before the feature existed. When enabled, the service is registered gracefully (a full attribute table is surfaced as a command error instead of asserting). The GUI home page no longer hard-disconnects on a single transient load error; it keeps the link and offers a retry. Also reclaimed ~12 KB of contended application RAM by relocating the 12 KB LF-ADC sample scratch buffer (`m_sample_storage`) into the otherwise mostly-unused retained NOINIT region — safe because its circular buffer is reset to empty before every read and never depends on zero-initialization (app free gap ~3.5 KB → ~15.5 KB). (@teo2peer)
