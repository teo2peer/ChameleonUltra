# Change Log
All notable changes to this project will be documented in this file.
This project uses the changelog in accordance with [keepchangelog](http://keepachangelog.com/). Please use this to write notable changes, which is not the same as git commit log...

## [unreleased][unreleased]
 - Perf: `MF1_HARDNESTED_ACQUIRE` now collects up to ~254 nonces per call (was 110) — the count byte caps it at 255, so the buffer is sized just under. Gathering the ~1400 nonces hardnested needs takes roughly half as many host round-trips / card re-selections, with no change to the on-card collection itself (@teo2peer)
 - BLE audit: added GATT **write** (write-with-response, returns the target's ATT status) as `ble write` / `bleGattWrite` and a per-characteristic Write button in the GUI (commands `BLE_GATT_WRITE`/`BLE_GET_WRITE` 7024-7025); and wired the single-target **link probe** (Ping) into the GUI (it previously only exposed the batch/global variant, which stays out of scope). The BLE GATT client is now complete: scan, connect, discover, read, write, subscribe, fuzz — all point-to-point against one target (@teo2peer)
 - Exposed firmware commands that had no CLI layer: `hf 14a field on|off` (`HF14A_SET_FIELD_ON/OFF` 2100/2101) and `hf des enum` — fast one-call DESFire enumeration decoding version/UID/AIDs/files via `HF14A_4_DESFIRE_SCAN` (6006). `hf mf autopwn`'s dump path also uses the single-auth sector read now. Added local docs under `docs/` (BLE audit + HF additions) (@teo2peer)
 - EMV: `emv scan` now gathers and displays more data elements — Application Effective Date (5F25), PAN Sequence Number (5F34), Application Currency Code (9F42, with ISO-4217 name), Language Preference (5F2D), Application Version (9F08), Application Interchange Profile (82, decoded SDA/DDA/CDA/CVM/TRM/IssuerAuth capabilities) and the Track2 service code (@teo2peer)
 - BLE audit UX: the directed fuzzer now shows that the single target is freed to reconnect to its normal source when the batch finishes, renamed the stop control to Cancel, and auto-disconnects the target when the batch completes or is cancelled (CLI + GUI). Added an outside-to-center LED animation (`rgb_marquee_ble_test_loop`) that runs on-device while a BLE test is in progress. Single-target flow only — no change to any batch/global mode (@teo2peer)
 - Added `MF1_READ_BLOCKS` (2018): authenticate once to a sector then read N consecutive blocks from it (far fewer auths than read-one-block per block when dumping). Exposed as `hf mf rdsc` in the CLI; `hf mf dump` now uses it (one auth per sector, falling back to per-block reads on any hiccup), and the GUI dump path uses it too (@teo2peer)
 - BLE audit follow-ups: `ble subscribe` now auto-discovers the characteristic's real CCCD descriptor (commands `BLE_FIND_CCCD`/`BLE_GET_CCCD` 7022-7023) instead of assuming value_handle+1, wired into CLI and GUI; and `ble scan`/`ble fuzz` gained `--out <file.json>` to export results (@teo2peer)
 - Extended BLE audit tools (targeted, receive-only): GATT notification/indication subscribe (`ble subscribe`, commands `BLE_SUBSCRIBE`/`BLE_GET_NOTIFICATIONS` 7020-7021) to stream a characteristic's values from the connected target; human-readable names for common SIG 16-bit service/characteristic UUIDs in scan/discover; a per-device advertising-details dialog in the GUI; and a local-advertising (discoverable) on/off toggle exposed in the GUI. All point-to-point against the one connected target or receive-only — nothing is broadcast (@teo2peer)
 - Improved BLE audit tools: `ble scan` now decodes the advertising data (flags, service UUIDs, manufacturer/company, TX power) and sorts by RSSI (`-v` for the full breakdown); the fuzzer emits a deterministic boundary-case corpus (empty, single/max-length 0x00 & 0xFF, incrementing) before random mutation; added GATT read of a characteristic value from the connected target (`ble read`, commands `BLE_GATT_READ`/`BLE_GATT_GET_READ` 7018-7019). Also wired into the Flutter GUI's BLE audit page (@teo2peer)
 - Added directed BLE GATT fuzzing harness (`ble connect`/`ble discover`/`ble fuzz`/`ble status`/`ble disconnect`): enables the SoftDevice central role to connect point-to-point to ONE operator-specified target address, enumerate its GATT characteristics, and write mutated payloads to a chosen characteristic to exercise its input parsing, detecting when the target drops the link. Scoped to a single connected target — never broadcasts. New file `ble_central.c`, commands `BLE_CONNECT`..`BLE_FUZZ_GET_LOG` (7010-7017); requires enabling `NRF_SDH_BLE_CENTRAL_LINK_COUNT=1` and a RAM-origin bump in `application.ld` (@teo2peer)
 - Added `ble scan` passive BLE scanner: uses the SoftDevice observer role in passive mode (active=0) to listen for nearby BLE advertisements and list device address, type, RSSI and advertised name. Listen-only — the device transmits nothing while scanning. New commands `BLE_SCAN_START`/`BLE_SCAN_STOP`/`BLE_SCAN_GET_COUNT`/`BLE_SCAN_GET_RESULTS` (7000-7003) (@teo2peer)
 - Added `hf mf readerkeys` reader-key capture mode (MFKey32): emulate a MIFARE Classic card (optionally from a dump), log the reader's authentication attempts, recover and export the reader's keys. Supports a fixed or random-per-activation UID, a center-out rainbow LED animation, and works over USB and BLE (@teo2peer)
 - Added `MF1_SET_RANDOM_UID_MODE`/`MF1_GET_RANDOM_UID_MODE` commands: emulate a new random UID on each reader activation (per-slot). Note: this fragments MFKey32 recovery and is meant for fingerprinting/testing (@teo2peer)
 - Added `MF1_SET_READER_KEYS_ANIM` command driving a non-blocking rainbow LED animation that radiates from the center of the LED bar outward (@teo2peer)
 - Changed MFC emulation to also log the auth nonce on a *successful* reader authentication (gated by detection), so reader keys can be captured even when the emulated dump already holds the reader's key (@teo2peer)
 - Added Jablotron LF protocol support: read, emulate and T55xx clone (@midlan)
 - Added IDTECK LF protocol support: tag emulation (PSK1 RF/32) and T55xx clone. No reader path yet; PSK demodulation on the envelope-only receive chain is left for a follow-up.
